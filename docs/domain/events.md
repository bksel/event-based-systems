# Event catalogue

Source: project proposal, Section 2.2. This is the authoritative list of event names. Code,
model and reports use these names exactly.

## Fault → service pairs

Service events are possible when the corresponding fault is active. Fault classes and blocked
resources are in [drinks and resources](drinks-and-resources.md#bf-resources-disabled-by-each-fault)
([ADR 0010](../decisions/0010-fault-classes-blocked-resources-and-fault-exits.md)).

| Fault | Cleared by | Notes |
|---|---|---|
| `water_empty` | `refill_water` | |
| `beans_empty` | `refill_beans` | |
| `milk_empty` | `refill_milk` | |
| `bin_full` | `empty_bin` | Also resets the grounds counter, `g := 0` |
| `tray_full` | `empty_tray` | |
| `brew_unit_removed` | `insert_brew_unit` | |
| `flow_error` | `clear_flow_error` | |
| `overheat` | `cooled_down` | Sensor event, not a user action. Boiler is `cold` afterwards |
| (descaling due, `d ≥ Ndue`) | `descaling_confirmed`, then `descaling_done` | Not a fault in `𝓕`, a counter condition |
